# Audio DSP and plugin engineering principles

These are the Oiko engineering rules for NicePlug Community and egui. They are design requirements and review criteria, not a claim that every future host or platform has already been tested. Baseline: NicePlug 0.3.0, nice-plug-egui 0.4.0, egui 0.36.1; use the checked lockfiles and the patch register for exact sources.

## Ownership and architecture

1. **Separate algorithms from hosting.** A DSP/core crate accepts plain values, slices, and explicit configuration. It imports neither NicePlug nor egui. A plugin crate translates host buffers, note events, transport, parameter changes, latency, and persistence into those core operations. Name modules for the responsibility they own, such as `particle_adapter`, `mts_client`, `parameter_controls`, or `display_data`. Split larger modules along concrete responsibilities such as parameter definitions, persisted state, editor interaction, history, and rendering. Keep product-specific implementations local. Consumers import internal APIs from their owning crate; update consumers when moving an API instead of retaining compatibility wrappers or re-exports.
2. **Give each thread clear ownership.** The audio thread owns live processing state. The UI owns interaction, painting, and resize requests. Workers own parsing, disk access, library scanning, and calls to external services whose execution time is not established. Editor closure must not stop processing.
3. **Share mechanisms, retain product identity.** Typography, DPI conventions, window adapters, the common palette, and generic numerical algorithms have one source. Product parameter IDs, DSP topology, layout, tuning policy, and interaction models stay local. Extract an existing mechanism when a second product needs it. Product integrations such as ODDSound/MTS stay in their consuming plugin or its own core crate. The shared DSP, UI, and host crates must not require those libraries or start their services. If an integration later needs sharing, use a separate crate that consumers explicitly depend on. Keeping a patch in the central vendor directory does not make it a dependency of every plugin.
4. **Make lifecycle obligations explicit.** Document prepare/activate, reset, process, reconfigure, and destroy. Allocate and create workers before audio starts. Reset must clear only prepared state. Shutdown/join, final Arc drops, and destruction of large resources must occur outside processing callbacks.

## Real-time guarantees

5. **Bound every audio operation.** No heap allocation/deallocation, mutex or condition-variable waits, spin-until-success loops, sleeps, filesystem/network calls, thread creation, formatting, logging, or graphics access in process or parameter-flush paths. Preallocate for the largest supported block, FFT, voice count, event queue, and scratch requirement. A non-automatable control can still change during processing and must follow these same rules.
6. **Preparation is part of correctness.** Precompute FFT plans, windows, interpolation tables, and frequency lookup data during activation. Select prepared configurations without dropping the old one on the audio thread. Use explicit FFT scratch buffers; do not assume a backend needs zero scratch.
7. **Choose communication by semantics.** Atomic scalars are appropriate for independent meters. Use a coherent bounded snapshot for a related parameter batch or tuning table. Use a bounded SPSC queue for ordered events, with an explicit full/empty policy. Audio makes one attempt and retains the last valid state on contention; it never waits for the editor. Keep communication values, flags, and memory ordering behind the protocol API. Use named internal parameter identities instead of numeric routing conventions. Document writers/readers and memory ordering. Only drop old resource ownership on a non-audio thread.
8. **Treat visuals as disposable observations.** Decimate audio-to-UI display data before publication; repaint at a UI rate. Meter loss or a closed editor cannot change sound. Mark approximate multi-scalar snapshots as such: a collection of atomics does not automatically provide a coherent frame.
9. **Audit native code too.** Rust ownership and an allocation guard do not prove that a C/C++ dependency or external runtime is real-time safe. Record the call path and its threading assumptions. Native dynamic loading, registration, ownership arbitration, and master publication belong outside process.
10. **Test rare transitions.** Allocation checks must cover resolution/quality changes, new maximum block sizes, state restore, silence, note floods, and transport changes, rather than steady playback alone. Memory safety tools and sanitizers supplement numerical and host tests; neither replaces them.

## Signal and musical correctness

11. **Specify units and numerical domains.** Names and API docs distinguish Hz, seconds, samples, cents, semitones, linear gain, decibels, and normalized parameters. Validate finite values at host/state/file boundaries. Define overflow, denormals, silence floors, and invalid configuration behavior.
12. **Preserve continuity intentionally.** Smooth appropriate continuous controls in a meaningful domain; do not smooth discrete selections blindly. Document bypass, reset, quality-switch transients, latency changes, tail length, and whether changes require a crossfade or host restart.
13. **Honor event timing.** Preserve supplied sample offsets for notes, automation, and supported modulation through the host adapter and into processing; do not silently round them to host-block boundaries. Instrument triggers and envelope starts must take effect at their specified sample. Document how parameter smoothing aligns with the timed event: a transition may start at the event or be centered on it. Centered smoothing requires sufficient advance event knowledge or lookahead, with any added processing latency reported to the host; its behavior must remain consistent across host-block boundaries. Precise event timing does not require an instantaneous audible jump. Document any coarser DSP update cadence, such as spectral-frame processing, separately from event delivery and reported latency. Verify timing with events inside blocks and across different block sizes, including coincident note and parameter changes. Do not infer finer automation detail than the host supplies. State what happens with stopped transport, sample-rate changes, loop/seek, and offline rendering. Inton's external MTS publication remains an explicit wall-clock control-rate exception; it does not provide sample-accurate tuning publication.
14. **Measure quality and cost.** Test impulse/DC response, frequency response, reconstruction, aliasing, modulation continuity, and deterministic output where applicable. Benchmark representative and worst-case sample rates, block sizes, channel/voice counts, and configurations. Record environment and numerical tolerances. Optimize measured bottlenecks while preserving reference implementations and their tests.

## Host contracts and UI

15. **Keep sessions compatible.** Plugin IDs, parameter IDs, enum values/ranges, serialization keys, and state versions are public contracts. Validate state atomically and reject malformed input without losing the current project. Validate stream lengths against platform representation limits and grow input buffers fallibly as data arrives. Product-specific size limits must not become universal framework limits. Preserve partial-read/write support. Inform the host when restored parameter values change.
16. **Use host gestures correctly.** Begin/set/end each parameter gesture through NicePlug. Complete an open gesture when an editor closes. Keep local undo from also triggering host undo. Capture only the shortcuts the editor owns.
17. **Distinguish scale from DPI.** Layout uses logical points; user zoom and monitor backing scale are different values. The shared adapter owns AppKit point/pixel conversion, while Linux and Windows delegate to the backend. Queue resizes after the egui UI pass to avoid callback re-entry. Validate restored zoom and preserve a usable default.
18. **Use shared typography roles.** Install fonts on editor creation/theme changes, with retained font licenses. Use common body/control/caption/title tokens even in custom painting. Keep four roles defined in the kit. Check text clipping, hit targets, keyboard navigation, and both themes across supported zoom steps; repaint behavior must not depend on audio activity.

## Maintainability and release quality

19. **Make builds reproducible.** Commit the root lockfile, declare a truthful MSRV, retain the reviewed dependency patches, and provide the complete workspace source set. Declare every workspace member's dependency role, product ownership where applicable, and integration dependencies in its Cargo metadata so boundary checks cover new crates automatically. Build/test core crates without graphics. Use formatting, warning-free Clippy, dependency boundary checks, and representative integration tests as gates.
20. **Patch once with an exit plan.** Keep a single maintained patch source, upstream revision, minimal diff, original notices, regression test, and removal criterion. Separate general fixes from product migrations and vendoring/packaging choices. Never imply a patch has been accepted upstream.
21. **Make failures diagnosable outside audio.** Report worker/build/load errors with useful context. Bound untrusted file/state sizes and native parser inputs. Explain unsafe invariants at the boundary; avoid broad lint silencing.
22. **Record what was tested.** Unit tests do not establish that an embedded window works in every host. Before release, exercise CLAP and VST3 on macOS, Windows, and Linux: open/close/reopen, multiple instances, state recall, resize/zoom/DPI changes, shortcuts, transport, suspension and offline mode. Keep unresolved platform checks visible and preserve existing limitations.
